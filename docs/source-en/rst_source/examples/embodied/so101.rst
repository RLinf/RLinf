SO-101 Setup & SFT
==================

.. figure:: https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobot/SO101_Follower.webp
   :align: center
   :width: 70%

   SO-101 follower with its gripper. Image: Hugging Face LeRobot.

Set up an SO-101 follower arm on Linux and run the complete workflow from calibration and hardware checks through leader teleoperation, LeRobot demonstration collection, OpenPI SFT, and local fixed-checkpoint evaluation.

Overview
--------

Every stage runs on the Linux machine wired to the arm and shares the ``SO101ReachEnv-v1`` joint-space representation across collection, SFT, and local evaluation.

Observation and Action
~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 24 76

   * - Field
     - Description
   * - Observation
     - Configured RGB camera frames plus canonical 6-D state (five absolute joint positions in radians and gripper opening in ``[0, 1]``).
   * - Action
     - Canonical 6-D target (five absolute joint angles in radians plus gripper opening ``0=closed, 1=open``), padded to 32-D for ``pi05_so101_joint``.
   * - Reward
     - Operator-labeled via keyboard during collection and evaluation (``a`` start/discard, ``b`` segment/failure, ``c`` success).
   * - Prompt
     - ``task_description`` in the collection and evaluation YAML configs (must match SFT).

Hardware and Safety
-------------------

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Component
     - Requirement
   * - Follower
     - SO-101 arm with gripper, servo controller, and kit power supply.
   * - Leader (optional)
     - SO-101 leader arm on a second USB serial port for teleoperation and data collection.
   * - Controller machine
     - Linux computer with USB connection(s) to the Feetech servo controller(s) and camera; GPU for OpenPI SFT and evaluation.

For an unassembled arm, follow the `LeRobot SO-101 guide <https://huggingface.co/docs/lerobot/so101>`__ and assign motor IDs individually before completing the daisy chain.

.. warning::

   On hardware, startup moves the follower to the folded rest pose ``[0, -99, 95, 65, 0]`` degrees along a paced trajectory (30 deg/s default; use ``--reset-speed 10`` for slower motion or ``--no-reset`` to skip startup movement). Clear that motion path before launching. RLinf workers do not run interactive calibration—calibrate the follower under the runtime account beforehand and never reuse the leader's calibration file for the follower.

.. dropdown:: Motor ID assignment for new or replaced servos

   For new or replaced Feetech motors, assign IDs and baud rates one motor at a time following the upstream wiring sequence (skip for an already configured arm):

   .. code-block:: bash

      lerobot-setup-motors \
        --robot.type=so101_follower \
        --robot.port=/dev/ttyACM0

   Connect only the motor named at each prompt. After all six motors are configured, finish assembly and reconnect the daisy chain.

Setup and Run
-------------

.. include:: _setup_common.rst

.. tab-set::

   .. tab-item:: 1. Setup & Calibration

      **1. Install RLinf**

      Install the SO-101 environment (includes OpenPI, LeRobot, and Feetech motor dependencies):

      .. code-block:: bash

         git clone https://github.com/RLinf/RLinf.git && cd RLinf
         bash requirements/install.sh embodied --model openpi --env so101 && source .venv/bin/activate

      **2. Find the serial port and check permissions**

      Plug in the follower servo controller and power supply, then identify the device path (examples assume ``/dev/ttyACM0``):

      .. code-block:: bash

         lerobot-find-port
         ls -l /dev/ttyACM0
         id -nG

      If the port belongs to ``dialout`` and your user is not in that group, run ``sudo usermod -aG dialout "$USER"``, log out and back in, reactivate ``.venv``, and recheck the port path.

      **3. Calibrate the follower**

      Calibrate the follower from a terminal before RLinf opens the serial bus (keep the calibration under the same user account and reuse ``--id rlinf_follower``):

      .. code-block:: bash

         lerobot-calibrate \
           --robot.type=so101_follower \
           --robot.port=/dev/ttyACM0 \
           --robot.id=rlinf_follower

      **4. Run the hardware check**

      Clear the fold path and test joints and gripper without cameras (``CAMERA_SERIALS=''`` skips camera discovery):

      .. code-block:: bash

         CAMERA_SERIALS='' python -m toolkits.realworld_check.test_so101_env \
           --port /dev/ttyACM0 --id rlinf_follower --step 2

      Enter commands one at a time, letting each move settle (``up``/``down`` step the shoulder by 2 degrees; use ``help`` for other joints; in env configs, ``reset_joint_speed`` is rad/s and ``reset_duration`` defaults to 3 s):

      .. code-block:: text

         where
         up
         down
         open
         close
         quit

   .. tab-item:: 2. Teleop & Collect

      **1. Calibrate the leader arm and verify teleoperation**

      Calibrate the SO-101 leader on its own port and ID, then launch teleoperation with camera discovery enabled (add ``--enable-camera-player`` to preview frames):

      .. code-block:: bash

         lerobot-calibrate \
           --teleop.type=so101_leader \
           --teleop.port=/dev/ttyACM1 \
           --teleop.id=rlinf_leader

         python -m toolkits.realworld_check.test_so101_env \
           --port /dev/ttyACM0 --id rlinf_follower \
           --leader /dev/ttyACM1 --leader-id rlinf_leader \
           --fps 30 --enable-camera-player

      After the follower folds, match its pose with the leader and type ``teleop``. Press Ctrl-C once to return to the prompt, then ``quit``. Camera capture runs independently (reusing frames up to ``camera_max_age`` = 0.5 s), and stalled gripper jaws hold at the measured opening to relieve pressure until the leader backs off (explicit open and close commands still wait for travel or stall relief).

      **2. Collect demonstrations**

      Set the follower/leader ports, calibration IDs, camera device, verified reset pose, and ``task_description`` in ``examples/embodiment/config/realworld_so101_collect_data_joint.yaml``, then launch from the repo root:

      .. code-block:: bash

         bash examples/embodiment/collect_data.sh realworld_so101_collect_data_joint

      Use ``a`` to start or discard a recording, ``b`` to advance a segment, ``c`` to save a successful episode, and ``q`` to stop cleanly. Set ``RLINF_KEYBOARD_DEVICE`` to a stable ``/dev/input/by-id/...`` path if multiple keyboards are attached. Episodes are written under the run's ``collected_data`` directory; to combine multiple runs or inspect recorded frames as MP4 previews, run ``toolkits/lerobot/merge_lerobot_datasets.py`` and ``toolkits/lerobot/visualize_lerobot_dataset.py`` before computing stats or starting SFT.

      **3. Compute OpenPI normalization statistics**

      Point ``HF_LEROBOT_HOME`` at the parent directory of your final dataset root and generate padded 32-D ``state`` and ``actions`` statistics:

      .. code-block:: bash

         export HF_LEROBOT_HOME=/absolute/path/to/datasets
         python -m toolkits.lerobot.calculate_norm_stats \
           --config-name pi05_so101_joint \
           --repo-id so101_dataset

      Copy the ``norm_stats.json`` path printed after ``Writing stats to:`` into ``openpi_data.norm_stats_path`` (``actor.model.openpi_data.norm_stats_path`` for SFT and ``rollout.model.openpi_data.norm_stats_path`` for evaluation; training and evaluation do not auto-discover this file beside ``full_weights.pt``).

   .. tab-item:: 3. SFT & Evaluate

      **1. Train OpenPI SFT**

      Edit ``examples/sft/config/realworld_sft_openpi_so101.yaml`` or pass the dataset root (containing ``meta/info.json``), base checkpoint, and ``norm_stats.json`` directly as Hydra CLI overrides:

      .. code-block:: bash

         bash examples/sft/run_vla_sft.sh realworld_sft_openpi_so101 \
           data.train_data_paths=./so101_dataset \
           actor.model.model_path=./pi05_base_pytorch \
           actor.model.openpi_data.norm_stats_path=./assets/pi05_so101_joint/so101_dataset/norm_stats.json

      **2. Evaluate locally with a fixed checkpoint**

      Update the follower port, calibration ID, camera device, verified reset pose, and identical ``task_description`` in ``examples/embodiment/config/realworld_so101_eval_openpi.yaml``. Set the trained checkpoint (compatible with ``pi05_so101_joint``) and matching ``norm_stats.json`` in ``examples/embodiment/config/model/so101_pi05.yaml``, or pass them via Hydra CLI overrides:

      .. code-block:: bash

         bash evaluations/run_eval.sh realworld_so101_eval_openpi \
           rollout.model.model_path=./logs/checkpoints/global_step_10000 \
           rollout.model.openpi_data.norm_stats_path=./assets/pi05_so101_joint/so101_dataset/norm_stats.json

      Press ``a`` to start an evaluation episode, ``c`` to record success, or ``b`` to record failure.

Results and Troubleshooting
---------------------------

Monitor SFT loss on the host with ``tensorboard --logdir ./logs --port 6006`` and confirm ``norm_stats.json`` contains 32-D ``state`` and ``actions`` arrays before launching SFT or evaluation; see :doc:`Training metrics <../../reference/metrics>` for metric names.

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Symptom
     - Fix
   * - Permission denied opening ``/dev/ttyACM0``
     - Run ``sudo usermod -aG dialout "$USER"``, log out and back in, reactivate ``.venv``, and re-verify the port with ``lerobot-find-port``.
   * - Worker fails to connect to follower
     - Run ``lerobot-calibrate`` under the same Linux account used for RLinf and pass the matching ``--id``; never reuse the leader's calibration file.
   * - Gripper stops advancing against an object
     - Stall protection holds the measured opening to relieve pressure; move the leader gripper slightly away from the obstruction before retrying.
   * - Multiple collection runs need joint SFT
     - SFT reads one dataset root and does not auto-merge runs; combine them into one LeRobot dataset first, then compute ``norm_stats.json`` on that combined dataset.
   * - Keyboard shortcuts do not register
     - Ensure the runtime user can read ``/dev/input`` and set ``RLINF_KEYBOARD_DEVICE`` to a ``/dev/input/by-id/...`` path.

For programmatic control or camera attachment, see :doc:`Robotics Interface <../../concepts/robotics>`; to build a custom task beyond ``SO101ReachEnv-v1``, see :doc:`New Real-World Tasks <../../extending/new_task>`.
