Wan RL
======

.. |huggingface| image:: /_static/svg/hf-logo.svg
   :width: 16px
   :height: 16px
   :class: inline-icon

.. figure:: https://raw.githubusercontent.com/RLinf/misc/main/pic/wan.png
   :align: center
   :width: 45%

   Wan as an action-conditioned world model.

Train a VLA policy **closed-loop without real robots or a physics simulator** by
using the **action-conditioned Wan world model** as the environment backend. Wan
generates future video frames from the current observation and an action
sequence, so the policy can be optimized on "imagined" rollouts with RL (GRPO/PPO).

Overview
--------

Train OpenVLA-OFT with GRPO on LIBERO suites simulated by the Wan world model.

Tasks
~~~~~

As a world model, Wan can fit many task settings behind a consistent interface. RLinf ships weights and init data for three LIBERO suites (each Wan checkpoint is trained from 1,500 VLA rollout trajectories):

.. list-table::
   :header-rows: 1
   :widths: 22 24 30 24

   * - Environment
     - Task / Suite
     - Config / Weights
     - Focus
   * - Wan
     - LIBERO-Spatial
     - ``RLinf/RLinf-Wan-LIBERO-Spatial``
     - Use Wan as a learned simulator for LIBERO spatial tasks.
   * - Wan
     - LIBERO-Object
     - ``RLinf/RLinf-Wan-LIBERO-Object``
     - Roll out object manipulation dynamics in the video world model.
   * - Wan
     - LIBERO-Goal
     - ``RLinf/RLinf-Wan-LIBERO-Goal``
     - Evaluate goal-conditioned rollouts through Wan.

Observation and Action
~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 24 38

   * - Field
     - Description
   * - Observation
     - RGB frames generated by the world model, ``[B, 256, 256, 3]``, seeded from initialization frames.
   * - Action
     - 7-D continuous actions normalized and tokenized to condition generation.
   * - Reward
     - World-model reward classifier output in ``[0, 1]``.
   * - Prompt
     - Natural-language task description used to condition the video world model.

Unlike a traditional simulator, Wan has no ``reset()``: it requires initialization frames and a task description, so you download an initialization dataset and point the config at it.

Setup and Run
-------------

.. include:: _setup_common.rst

Select a LIBERO suite tab for NVIDIA CUDA, or switch to **Huawei Ascend CANN** for Ascend NPU.

.. tab-set::

   .. tab-item:: LIBERO-Spatial
      :sync: spatial

      **1. Install**

      .. code-block:: bash

         git clone https://github.com/RLinf/RLinf.git && cd RLinf
         bash requirements/install.sh embodied --model openvla-oft --env wan && source .venv/bin/activate

      **2. Download**

      Download the OpenVLA-OFT SFT checkpoint together with the Wan world-model weights and initialization dataset:

      .. code-block:: bash

         hf download Haozhan72/Openvla-oft-SFT-libero-spatial-traj1 --local-dir ./Openvla-oft-SFT-libero-spatial-traj1
         hf download RLinf/RLinf-Wan-LIBERO-Spatial --local-dir ./RLinf-Wan-LIBERO-Spatial

      **3. Launch**

      Set the two downloaded checkpoint paths in ``examples/embodiment/config/wan_libero_spatial_grpo_openvlaoft.yaml`` (rollout inherits ``actor.model.model_path`` automatically):

      .. code-block:: yaml

         actor:
           model:
             model_path: ./Openvla-oft-SFT-libero-spatial-traj1
         env:
           train:
             wan_wm_hf_ckpt_path: ./RLinf-Wan-LIBERO-Spatial

      Launch training with ``run_embodiment.sh``:

      .. code-block:: bash

         bash examples/embodiment/run_embodiment.sh wan_libero_spatial_grpo_openvlaoft

   .. tab-item:: Huawei Ascend CANN
      :sync: ascend

      Use an Ascend host or container with CANN and the NPU driver available. Wan generates observations directly from the world model, so this training workflow does not require the LIBERO simulator or OSMesa rendering.

      **1. Install**

      Create an environment with the OpenVLA-OFT policy and Wan world-model dependencies:

      .. code-block:: bash

         git clone https://github.com/RLinf/RLinf.git && cd RLinf
         bash requirements/install.sh --platform ascend embodied --model openvla-oft --env wan && source .venv/bin/activate

      The installer adds the matching ``torch-npu`` package and skips CUDA flash-attention. Install MindIE-SD separately in this activated environment, using a build compatible with your CANN and PyTorch versions. The installer does not install MindIE-SD.

      Check that the NPU is available and the required MindIE-SD operators can be imported:

      .. code-block:: bash

         python - <<'PY'
         import torch
         import torch_npu
         from mindiesd import rotary_position_embedding
         from mindiesd.layers.flash_attn.attention_forward import attention_forward

         assert torch.npu.is_available(), "No Ascend NPU is available"
         PY

      When the Wan backend runs on NPU, RLinf automatically enables accelerated attention, rotary embeddings, and RMSNorm before constructing the pipeline. If the dependencies cannot be imported, it logs a warning and keeps the original diffsynth operators. This setup covers the Wan backend; validate the policy checkpoint's numerical behavior separately on your target hardware.

      **2. Download**

      Download the OpenVLA-OFT SFT checkpoint and Wan world-model weights for your suite (example: LIBERO-Spatial):

      .. code-block:: bash

         hf download Haozhan72/Openvla-oft-SFT-libero-spatial-traj1 --local-dir ./Openvla-oft-SFT-libero-spatial-traj1
         hf download RLinf/RLinf-Wan-LIBERO-Spatial --local-dir ./RLinf-Wan-LIBERO-Spatial

      **3. Launch**

      Set the policy and world-model paths in ``examples/embodiment/config/wan_libero_spatial_grpo_openvlaoft.yaml`` and keep ``runner.val_check_interval: -1`` and ``runner.only_eval: False`` as in the default config to train in Wan with simulator evaluation disabled:

      .. code-block:: yaml

         actor:
           model:
             model_path: ./Openvla-oft-SFT-libero-spatial-traj1
         env:
           train:
             wan_wm_hf_ckpt_path: ./RLinf-Wan-LIBERO-Spatial

      Launch the Wan LIBERO-Spatial GRPO recipe from the repository root:

      .. code-block:: bash

         bash examples/embodiment/run_embodiment.sh wan_libero_spatial_grpo_openvlaoft

.. dropdown:: Advanced configuration (optional)

   Because the world model does not provide proprioception or wrist views and uses a fixed chunk length, ``actor.model`` defaults to ``use_proprio: False``, ``num_images_in_input: 1``, and ``num_action_chunks: 8``. If you switch to another LIBERO suite, update ``actor.model.unnorm_key`` to match the SFT checkpoint.

   Optional environment knobs under ``env.train``:

   - ``enable_kir``: enable KIR (KeyFrame-Init Rollout). When ``False``, resets sample only ``.npy`` files without ``_kir`` in their names; when ``True``, resets sample from all initialization files in ``dataset/``.
   - ``num_inference_steps``: world-model denoising steps (default ``5``). Fewer steps run faster at lower visual quality; single-step generation can still improve policy performance.
   - ``reward_model.type``: reward model type — ``ResnetRewModel`` or ``TaskEmbedResnetRewModel``.
   - ``terminate_at_max_episode_steps``: how an episode that reaches ``max_episode_steps`` ends. Default ``False`` reports a truncation, so with ``auto_reset: True`` RLinf bootstraps the value of the final observation onto the last reward. Set ``True`` when ``max_episode_steps`` is the task's own horizon (for example, an episode-level success reward given once at the end), so the episode terminates without value bootstrapping under ``algorithm.bootstrap_type: standard``. Keep ``False`` when the limit cuts a longer task short, such as short rollouts started from KIR keyframes. ``True`` requires ``auto_reset: True``.

Visualization and Results
-------------------------

Watch ``env/success_once`` in TensorBoard (``tensorboard --logdir ./logs``); set ``env.eval.video_cfg.save_video=True`` to record videos, or see :doc:`Training metrics <../../reference/metrics>` for W&B/SwanLab and all metrics.

We evaluate every ``task_id`` × ``trial_id`` combination across the Object, Spatial, and Goal
suites — 1500 environments in total (10 tasks × 150 trials). For both SFT and RL-trained
models we use ``do_sample = True`` and ``temperature_train = 1.6`` in ``rollout.sampling_params``,
with ``reset_gripper_open = True``.

.. note::

    Wan training and inference are built on
    `Diffsynth-Studio <https://github.com/RLinf/diffsynth-studio>`_. In the results below we
    use a **frozen** world model to serve the RL training of the VLA policy, without
    co-evolution between the world model and the VLA. You can implement co-evolution manually
    for further gains.
