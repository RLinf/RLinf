SO101 配置与控制
================

本页介绍如何配置 SO101 follower 与 leader、检查两台机械臂，并通过固定的 episode reset 状态采集关节空间示范数据。

.. figure:: https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobot/SO101_Follower.webp
   :align: center
   :width: 70%

   SO-101 follower 及其夹爪。图片来源：Hugging Face LeRobot。

概览
----

硬件检查和示范数据采集都在连接机械臂的 Linux 主机上运行，无需 GPU 或模型 checkpoint。先检查 follower，再分别完成两台机械臂的标定，最后使用采集配置，让每个 episode 从相同的关节与夹爪状态开始。

硬件配置
--------

安装软件前，先准备机械臂及其控制主机。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 组件
     - 要求
   * - Follower
     - SO-101 机械臂及其夹爪、舵机控制板和套件指定的电源。
   * - 控制主机
     - 通过 USB 连接 follower 舵机控制板的 Linux 计算机。

未组装的机械臂请先参考 `LeRobot SO-101 指南 <https://huggingface.co/docs/lerobot/so101>`_ 中的零件清单与组装说明。完成接线前，需要逐个配置新电机；下方安装流程包含相应命令。

安装
----

在控制主机上按下方自定义环境流程安装机器人依赖。后续检查均在同一仓库目录和已激活的环境中运行。

机器人控制节点
~~~~~~~~~~~~~~

在连接机器人的主机上克隆 RLinf，然后安装对应环境。

.. include:: _setup_common.rst
   :end-before: 然后，使用

在仓库根目录安装机器人依赖：

.. code-block:: bash

   # Mainland China users can add --use-mirror for faster downloads.
   bash requirements/install.sh embodied --env so101
   source .venv/bin/activate
   export REPO_PATH="$PWD"

安装脚本包含 LeRobot 及 Feetech 支持。后续命令均在此仓库目录中运行，并保持环境已激活。平台要求见 :doc:`安装 </rst_source/start/installation>`。

查找串口并配置电机
^^^^^^^^^^^^^^^^^^

连接舵机控制板的 USB 线缆，以及套件指定的电源。先查找 follower 对应的串口：

.. code-block:: bash

   lerobot-find-port

按提示拔下 USB 线缆，再重新接入。工具报告的设备路径就是后续使用的串口；以下示例假设为 ``/dev/ttyACM0``。检查设备权限和当前用户组：

.. code-block:: bash

   ls -l /dev/ttyACM0
   id -nG

在 Ubuntu 上，如果串口属于 dialout 组，运行程序的账号也需要加入该组。若尚未加入，执行 ``sudo usermod -aG dialout "$USER"``，退出登录并重新登录，然后回到仓库目录，重新激活 ``.venv``。USB 重新接入后，应再次确认串口路径。

新电机或更换后的电机需要按上游指南的接线顺序，逐个设置 ID 与波特率；此步骤通常只需执行一次：

.. code-block:: bash

   lerobot-setup-motors \
     --robot.type=so101_follower \
     --robot.port=/dev/ttyACM0

每次仅将提示中指定的电机连接到控制板。工具设置该电机的 ID 和波特率后，才会提示连接下一个。6 个电机全部配置完成后，按指南完成组装并恢复串联接线。已配置好的机械臂可跳过电机配置，但仍需使用 RLinf 将采用的 ID 完成标定。

标定 Follower
^^^^^^^^^^^^^

电机配置与组装完成后，在终端中标定 follower，再让 RLinf 打开串行总线：

.. code-block:: bash

   lerobot-calibrate \
     --robot.type=so101_follower \
     --robot.port=/dev/ttyACM0 \
     --robot.id=rlinf_follower

将串口替换为实际设备。按照指南将关节移到中间位置并确认提示，再按要求逐个移动关节，覆盖其运动范围。工具会报告保存的标定文件；请保留在运行 RLinf 的账号下，并使用相同的 ``--id rlinf_follower``。leader 使用独立的 calibration ID 和文件。

.. warning::

   标定由操作员在启动 worker 前完成。RLinf worker 会读取配置 ID 对应的标定文件，因此请使用运行机械臂的账号保存标定结果。

运行
----

follower 标定完成后，使用交互式测试检查关节与夹爪。脚本可能启动本机 Ray 实例，用于与机械臂通信。

.. warning::

   在硬件模式下，启动时会将 6 个舵机移动到标准状态。5 个关节的目标角约为 ``[-4, -63.8, 33.6, 83.6, -91.8]`` 度，夹爪目标为 ``0..1`` 开度范围内的 ``0.013``。启动前请清空两台机械臂的运动路径。添加 ``--no-reset`` 可仅建立连接，不发送启动运动命令。

确认 follower 已标定，且 reset 轨迹的路径无遮挡后，运行：

.. code-block:: bash

   CAMERA_SERIALS='' python -m toolkits.realworld_check.test_so101_env \
     --port /dev/ttyACM1 --id rlinf_follower --step 2

将串口替换为实际设备，ID 使用标定时的值。``CAMERA_SERIALS=''`` 关闭相机发现，使测试只使用机械臂。

启动 reset 与 ``home`` 命令都会将关节和夹爪移动到标准状态。关节轨迹从实测位置开始平滑移动，默认速度上限为每秒 30 度；使用 ``--reset-speed 10`` 可降低速度。在 env 配置中，``reset_joint_qpos`` 与 ``reset_gripper_position`` 共同定义完整状态，``reset_joint_speed`` 的单位为弧度每秒，``reset_duration`` 设置轨迹的最短时间。

逐条输入以下指令，每次运动完成后再继续：

.. code-block:: text

   where
   up
   down
   open
   close
   park
   quit

``up`` 和 ``down`` 分别将肩关节角度增加或减少 2 度。每次关节运动后会打印反馈；``open`` 与 ``close`` 用于测试夹爪。需要折叠机械臂时，先运行 ``park`` 移动到配置的 park 状态，再运行 ``quit`` 关闭环境及其机械臂 worker。关闭 session 只释放资源。输入 ``help`` 可查看其他关节方向。

在自己的程序中控制机械臂或接入相机，请参考 :doc:`机器人接口 </rst_source/concepts/robotics>`。

使用 Leader 控制机械臂
-----------------------

要通过手动操作控制 follower，请连接 SO101 leader，并使用它自己的端口和 calibration ID 完成校准：

.. code-block:: bash

   lerobot-calibrate \
     --teleop.type=so101_leader \
     --teleop.port=/dev/ttyACM0 \
     --teleop.id=rlinf_leader

为两台机械臂配置端口后启动检查。未设置 ``CAMERA_SERIALS`` 时会自动发现相机；添加 ``--enable-camera-player`` 可显示图像：

.. code-block:: bash

   python -m toolkits.realworld_check.test_so101_env \
     --port /dev/ttyACM1 --id rlinf_follower \
     --leader /dev/ttyACM0 --leader-id rlinf_leader \
     --fps 30 --enable-camera-player

follower 到达标准状态后，将 leader 放到相同姿态，再输入 ``teleop``。follower 会持续跟随关节和夹爪运动。按一次 Ctrl-C 返回命令提示符，再输入 ``quit`` 断开连接。

``--fps`` 设置目标控制频率，默认为 30 Hz。相机独立采集图像；环境会复用不超过 ``camera_max_age`` 秒的图像（默认 0.5 秒），每个控制 step 不等待新的图像。连续夹爪命令不等待运动完成。驱动会监测夹爪停滞，并将目标保持在实测开度以释放压力。每次检测到夹爪向目标进一步移动时，驱动都会重新开始停滞检测，因此缓慢或持续的运动只要仍在前进就可以继续。需要再次向受阻方向运动时，先将 leader 的夹爪向远离该开度的方向移动。驱动的 ``open_gripper()`` 和 ``close_gripper()`` 方法仍会等待运动完成或压力释放。

采集示范数据
------------

两台机械臂均通过检查后，使用 SO-101 采集配置，让每个录制 episode 从同一个状态开始。先在 ``examples/embodiment/config/realworld_so101_collect_data_joint.yaml`` 中填写 follower 与 leader 的串口和 calibration ID，再运行：

.. code-block:: bash

   bash examples/embodiment/collect_data.sh \
     realworld_so101_collect_data_joint

WSL 等没有 ``/dev/input`` 的 Linux 环境可以为 keyboard wrapper 使用控制文件。启动采集前设置文件：

.. code-block:: bash

   export RLINF_KEYBOARD_CONTROL_FILE=/tmp/rlinf_so101_control
   : > "$RLINF_KEYBOARD_CONTROL_FILE"
   bash examples/embodiment/collect_data.sh \
     realworld_so101_collect_data_joint

在另一个终端追加命令，每条命令只会消费一次：

.. code-block:: bash

   echo start >> /tmp/rlinf_so101_control
   echo segment >> /tmp/rlinf_so101_control
   echo success >> /tmp/rlinf_so101_control

``abort`` 会停止当前录制，但不会移动机械臂。同一输入入口在评测时接受 ``failure``，在显式 DAgger 控制中接受 ``intervene`` 和 ``release``。

首次 reset 以及每个 episode reset 都会同时启动 leader 和 follower 轨迹，两台机械臂的 5 个关节与夹爪一起移动到配置的标准状态；等待下一条录制时 leader 保持扭矩。脚踏板使用 ``start_end`` 流程控制录制：``a`` 触发交接倒计时，倒计时结束后 leader 卸力并交给操作员；录制中再次按 ``a`` 会放弃当前录制，``b`` 切换 segment，``c`` 会先让 leader 保持当前位置并给操作员清空机械臂的时间，再将 episode 标记为成功并保存。交接时间由 ``manual_start_hold_seconds`` 配置。配置会把最终的 LeRobot 数据集写入本次运行目录下的 ``collected_data``。

采集发生异常时，runner 会让 leader 与 follower 同时进入配置的 park 状态，然后关闭两侧连接并卸力。如果安全运动本身失败，系统会记录该错误并继续执行关闭流程。

park 状态通过显式命令触发。需要 park 时，在交互检查中运行 ``park``；结束采集或调用 ``close()`` 只释放设备。

Policy 部署与远程 gRPC 采集
----------------------------

启动机器人侧评测前，先选择 policy 的部署位置：

* 本地 OpenPI checkpoint 通过标准 embodied evaluation 入口运行。checkpoint 位于机器人主机时，设置 ``rollout.model.model_path``：

  .. code-block:: bash

     python evaluations/eval_embodied_agent.py \
       --config-path examples/embodiment/config \
       --config-name realworld_so101_eval_openpi \
       rollout.model.model_path=/path/to/checkpoint

* 外部 GPU 主机运行 standalone service。先在 GPU 主机启动服务，并确保机器人主机可以访问监听地址：

  .. code-block:: bash

     python examples/embodiment/serve_policy.py \
       --config-name realworld_so101_policy_server \
       model.model_path=/path/to/checkpoint \
       server.host=0.0.0.0 server.port=50052 \
       server.policy_id=so101-pi05

  机器人主机进行固定 checkpoint 评测时使用 ``realworld_so101_eval_openpi_grpc``；需要同时保存人工干预 episode 供后续离线训练时使用 ``realworld_so101_grpc_dagger_offline``。

本地 OpenPI 入口要求机器人主机安装 OpenPI 并能读取 checkpoint。gRPC 入口把 OpenPI 保留在 policy 主机；机器人侧进程发送观测，接收 6 维绝对关节动作。

远程 gRPC DAgger
----------------

固定 checkpoint 的 gRPC 流程将 policy 放在 GPU 主机上，而 SO-101 硬件环境仍在本地运行。先在 GPU 主机启动 policy service，再在本地显式设置 service 地址、policy ID、follower 串口、leader 串口和 calibration ID，启动评测入口：

.. code-block:: bash

   export SO101_SERVER_ADDRESS="${GPU_HOST}:50052"
   export SO101_POLICY_ID=so101-pi05
   export SO101_FOLLOWER_PORT=/dev/ttyACM1
   export SO101_LEADER_PORT=/dev/ttyACM0
   export SO101_FOLLOWER_ID=rlinf_follower
   export SO101_LEADER_ID=rlinf_leader
   export SO101_CAMERA=/dev/video0
   export SO101_EVAL_CONFIG=realworld_so101_grpc_dagger_offline
   bash examples/embodiment/run_so101_experiment.sh eval \
     env.eval.rollout_epoch=10

服务端必须返回与本地配置一致的 policy ID、动作维度 ``6`` 和 action horizon ``20``。入口复用 RLinf 现有 evaluation runner 和 LeRobot writer。OpenPI 在 policy 主机运行，机器人主机只运行 gRPC client 和硬件环境。WSL 没有键盘设备时，可以通过入口脚本的控制文件发送命令：

基础评测配置将单个 rollout window 限制为 ``1800`` 个硬件步；在默认 15 Hz 控制频率下约为两分钟，并且这个上限可以被 policy 的 20 步 action chunk 整除。通过命令行覆盖 ``env.eval.rollout_epoch`` 可以指定本次运行的 rollout window 数量，同一份配置适用于任意数量。运行过程中用 ``c`` 或 ``a`` 结束当前 episode。评测会在达到配置的 rollout 数量后正常结束，因此评测控制接口不提供 ``q`` 命令；只有需要提前中断时才使用进程级中断。每个 window 到达上限时都会丢弃当前 action chunk，执行配置中机器人和 teleop 设备的复位流程；下一个 window 会等待 ``s`` 后才重新请求 policy action。

.. code-block:: bash

   bash examples/embodiment/run_so101_experiment.sh control s
   bash examples/embodiment/run_so101_experiment.sh control space
   bash examples/embodiment/run_so101_experiment.sh control r
   bash examples/embodiment/run_so101_experiment.sh control c
   bash examples/embodiment/run_so101_experiment.sh control a

``s`` 启动 policy rollout，``space`` 请求显式接管 leader，``r`` 将 leader 交还给 policy，``c`` 保存成功 episode，``a`` 标记失败 episode。接管和交还 leader 时都会使用三秒 handover buffer，让操作员有时间握稳或移开 leader。生成的 LeRobot 数据写入本次运行目录下的 ``collected_data``。上传 episode 并执行离线训练属于后续步骤；固定 checkpoint service 在本次运行中保持已部署权重不变。

新增真机任务
------------

硬件检查通过后，参考 :doc:`新增真机任务 </rst_source/extending/new_task>` 定义任务的复位流程、观测、动作、奖励和成功条件。开始训练前，需要先实现可运行的真机任务。
