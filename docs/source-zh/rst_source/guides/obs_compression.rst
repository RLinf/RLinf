观测压缩
========

在具身任务中，图像观测是 Env :math:`\rightarrow` Rollout 通道上的主要负载。在带宽
受限或多机场景下，传输这些图像帧会拖慢 rollout 吞吐。RLinf 可以在传输前对其进行
**无损**\ 压缩，并在 Rollout 端还原，用少量 CPU 时间换取显著更小的网络传输量。

该功能**默认关闭**；开启后完全透明：还原出的观测与原始数据逐比特一致，不影响训练
结果。

工作原理
--------

只有观测负载中的 ``uint8`` 图像张量会被压缩；本体状态、标志位与文本字段原样透传。
每个被压缩的张量会被替换为一个自描述的标记（marker），因此解压端无需任何配置，也
不保留跨消息状态。

每条消息会执行两步：

- **XOR-delta（可选）**：将 batch 维上相邻的帧做逐字节异或。并行的具身环境（如
  LIBERO、ManiSkill）渲染的背景大多是静态的，因此差值大部分为零，比原始帧压缩得
  更好。
- **熵编码**：使用 ``lz4``\ （最快）或 ``zstd``\ （压缩率更好）压缩结果。

``lz4`` 与 ``zstandard`` 编解码器已作为核心依赖随 RLinf 一并安装，无需额外安装。

如何开启
--------

在具身配置的 ``env`` 下添加 ``obs_compression`` 块：

.. code-block:: yaml

   env:
     obs_compression:
       enable: true      # 默认关闭
       codec: lz4        # lz4（更快）或 zstd（压缩率更好）
       level: 1          # zstd 压缩级别；lz4 会忽略
       xor_delta: true   # 压缩前对相邻帧做异或

其中：

- ``enable`` 开启该功能。省略或为 ``false`` 时观测不压缩，零开销。
- ``codec`` 选择后端。``lz4`` 追求最低 CPU 开销；``zstd`` 追求最高压缩率。
- ``level`` 为 ``zstd`` 的压缩级别（越高越小但越慢）。
- ``xor_delta`` 开启 XOR-delta 预处理。当一条消息只有单帧时会自动跳过。

预期收益
--------

在连续的 LIBERO 观测上（每个 Env Worker 每步约 3 MiB 图像），无损压缩通常可将负载
降到原始大小的约 36%–41%：

.. list-table::
   :header-rows: 1
   :widths: 40 20 20 20

   * - 配置
     - 相对原始大小
     - 压缩
     - 解压
   * - XOR + LZ4
     - ~40.5%
     - ~2.65 ms
     - ~0.66 ms
   * - XOR + Zstd（level 1）
     - ~36.0%
     - ~4.70 ms
     - ~1.93 ms

实际压缩率取决于图像分辨率以及场景的静态程度。
